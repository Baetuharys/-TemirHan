# Lifecycle

This library follows a MergenHan-inspired two-axis lifecycle.

## Structural types

- module — reusable behavior, constraint, domain knowledge, tone, or output fragment
- master — orchestrates multiple modules for a task family
- blueprint — stabilized skill draft before packaging
- skill — packaged reusable capability
- adapter — runtime-specific compatibility layer

## Maturity

- draft
- active
- stable
- deprecated
- archived

Adapters are compatibility mappings, not maturity stages.
